# 新闻首页板块与阅读层级

调研与设计日期：2026-10-23。目标是重新组织新闻内容的主次、密度和入口，保留已经认可的原创艺术首屏与滚动场景。读者进入正文区后，应能依次找到重点报道、完整新闻列表、主题档案和订阅方式。

本记录区分三类内容：官方页面实际可读的结构、据此作出的设计选择，以及尚待验收的界面。参考站的新闻正文、图片、标识和源码不作为本站素材；未读取或推测这些站点的流量与转化效果。

## 调研来源与观察边界

英文站通过 web 工具读取官方 AI 栏目的公开正文结构。中文站由主任务使用已认证 Firecrawl 采集，本记录另行读取 `.firecrawl/newsroom-qbit.md`、`.firecrawl/newsroom-jiqizhixin.md` 核对。文本提取可证明栏目、信息顺序与入口存在，不能代替桌面或手机的像素布局、折叠行为及交互验收。

原计划中的 MIT Technology Review AI 栏目被其 robots 规则拒绝抓取，未将搜索摘要当作该页实测结果；改看 MIT News 的官方 AI 栏目。两者是不同站点，以下保留准确名称。

| 官方页面 | 实际观察 | 对本站的设计启发 |

## 本次采用的内容顺序

1. **焦点报道：一条重点、两条辅助。** 用真实文章标题、日期、摘要和图片表达编辑主次。重点与辅助共同构成首组报道，避免三张同权重的大卡片。缺图时使用明确占位，不替文章生成假新闻现场。
2. **新闻一览：完整新闻流，周报与深读另列。** 列表提供“标题／摘要”密度开关，服务快速扫描和稍详细阅读；搜索、筛选及分页仍使用真实查询结果。周报或长篇内容在独立区块提供背景阅读，不把长文列表称为全天快讯。
3. **主题档案：主题与系列入口。** 主题帮助按议题查找，系列帮助连续阅读；二者沿用真实路由和现有数据关系。没有数据的模块采用明确空态或隐藏可选内容，不补造计数和热度。
4. **阅读与订阅：放在主要内容之后。** 汇总 RSS、订阅与继续阅读入口，不在扫描新闻时反复插入订阅大卡。

艺术场景继续负责刊物识别，以上结构负责正文阅读。装饰画面不承担新闻事实；日期、来源与内容类型来自实际文章字段。当前数据主要是已发布的历史报道，板块改革不代表采集流水线已经恢复，也不代表已实现独立快讯采集或全量人工审校。

## 章节目录的一致性

封面与浮动目录共同读取 `frontend/src/utils/editionChapters.js`，使用以下顺序。现有锚点保留，因此旧分享链接和刷新定位不因文案调整失效。

| 序号 | 标题 | 保留的锚点 |
| --- | --- | --- |
| I | 焦点报道 | `edition-focus` |
| II | 新闻一览 | `edition-news` |
| III | 主题档案 | `edition-topics` |
| IV | 阅读与订阅 | `edition-reading` |

目录统一读取共享数据。封面场景、观察器和激活逻辑延续原有实现；桌面浮动目录缩为罗马数字，并为每个链接提供明确的 `aria-label`，保留可访问名称。

## 手机端迁移原则：设计推断

以下是本站的布局选择，不是对参考站手机界面的实测结论：

- 按“重点报道 → 两条辅助 → 新闻一览 → 周报／深读 → 主题与系列 → 订阅”形成单列顺序。桌面辅助栏在窄屏移到主新闻列表之后，不能挤压正文宽度。
- 标题、真实日期与内容类型优先保留；摘要由密度开关控制，避免手机首屏被多张大封面耗尽。
- 搜索、筛选和分页保持可达，并保留查询参数；浮动目录、筛选栏和订阅条不能同时遮挡阅读或按钮。
- 保留减少动态效果、键盘导航和报刊版选择，内容浏览不依赖 WebGL 成功。

## 验收状态

新版已落实焦点三篇、独立周报、紧凑新闻流、真实主题与系列、订阅区。React 与无 JavaScript 的预渲染共用文章分配逻辑，避免同一篇文章在多个板块重复。构建复用已有主题、系列和周报请求提供首屏数据，运行时补充请求独立加载；主题失败与周报失败分别归因。搜索与分页的结果按查询隔离，返回首页失败时不会将旧结果当作焦点。

本地前端完整测试 83 个文件、444 项通过；最后数据归因和预渲染排序修正另有 25 项定向回归通过。覆盖文章去重、目录锚点、真实日期、密度切换、搜索失败、补充模块独立重试、首屏数据投影以及 HTML/脚本注入边界。正式 API 构建复核完整生成 88/88 个主题、5/5 个系列、141/141 篇文章；首次构建有一篇历史文章请求超时，复核后全部生成。浏览器验收结果完成后补记；组件测试通过不能代替视觉验收。

实页需确认：桌面重点与辅助的层级、手机单列顺序与横向溢出、密度开关、搜索筛选分页、独立周报／深读、主题和系列路由，以及封面与浮动目录的四个目标均对应最终内容区。最终测试、构建及部署结果以本轮变更记录为准。
