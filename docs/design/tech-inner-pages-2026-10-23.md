# 科技版内页：构图、层次与轻量动态

调研日期：2026-10-23。范围为日报、周报、主题／系列、搜索与文章阅读页。已经认可的首页艺术首屏保留，本记录不提出重新生成首页素材或替换首页场景。

这次改版应让读者从构图上识别内容类型：日报用于按日期扫描，周报用于理解一周脉络，主题用于持续查阅，文章页用于阅读原文与来源。仅改变背景颜色、按钮颜色和卡片边框，不能完成这个目标。

## 五项可实施的设计建议

### 1. 日报页改成日期主导的“信号档案”

**本站设计推断：** 首屏采用不对称构图：左侧是大字号“日报”和真实覆盖日期，右侧是一块较浅的坐标／刻度图形；下方直接接按真实日期分组的报道时间轴。首条报道占主栏，后续报道用紧凑行，日期索引保持较低视觉权重。不要再用“图标＋栏目标题＋一句介绍＋等大卡片”作为整个页面。

频道图形可用原创 SVG 的日期刻度、信号轨迹和一条短暂扫过的高亮线。轨迹属于频道身份装饰，应与真实数据区分；没有小时级数据，就不画“每小时事件分布”、不写 LIVE，也不把历史日报标成今天。使用既有覆盖日期或发布日期，日期缺失时如实说明。

手机上先显示日期与首条报道，再进入列表；日期索引折叠为选择器或横向日期入口，不把桌面侧栏压到正文旁。搜索与分页仍连接现有查询状态。

### 2. 周报页采用有封面与目录的“期刊阅读”

**本站设计推断：** 首屏以一份真实周报作为主体：大期刊标题、真实覆盖区间与文章封面共同构成主视觉，旁边放本篇可验证的章节入口或简短摘要；历史期次以较窄的封面／标题列表排列。由大封面、文字留白和明确的前后层次制造冲击力，与日报的紧凑时间轴形成区别。

可以用轻微错位的两层纸面与投影表现“期刊展开”，不必增加三维渲染。只有确实存在的历史周报才能作为后一层封面；纯装饰纸面不标期号或新闻标题。若后端未提供期号，不推算“第几期”；覆盖区间缺失时，只展示已知覆盖日期或发布日期。正文缺少结构化目录时，使用文章摘要与全文入口，不凭空生成章节。

阅读页继续使用稳定单栏正文，并提供真实标题生成的目录。封面层次停留在刊物入口，不能让长文每段都漂浮或倾斜。

### 3. 主题与系列页成为可查阅的“知识档案”

**本站设计推断：** 用索引轨道、标题与一条主要内容面形成档案构图。主题页突出议题、真实文章数、最近发布日期和相关报道；系列页突出连续阅读顺序。两类页面共用导航位置，但主题按查阅组织，系列按阅读序列组织，不能只是换一个小图标。

Geist 的装饰引导线可转化为页头或主题索引的细网格、十字定位点与编号。其余列表保持开放布局，不把每条报道再包进发光盒子。不存在明确主题关联的数据时，不画暗示关联强度的网络图；常用关键词入口也不冒充算法生成的知识图谱。

搜索／归档沿用这一套档案语法，但视觉主体换成查询词、结果数与日期分组，保持真实的筛选、空态和重试。装饰网格不参与焦点顺序。

### 4. 共用位置栏与视图栏，用三层文面建立深度

**本站设计推断：** 参考 Linear 的层级思路，把“我在哪里”和“如何浏览”拆开：页头是面包屑、栏目名及主动作；内容面顶部才是类型、日期、筛选、显示方式等视图控件。导航不能比本页报道更亮、更大，控制按钮也不散落在每张卡片四周。

页面只建立三个清晰层次：低饱和背景、承担频道身份的视觉面、承载实际阅读的主文面；真正浮出的菜单与预览再使用浮层。可通过面的位置、尺度差、细边缘和小范围投影建立深度，避免全屏模糊、多层玻璃与每张卡片相同的强阴影。深色或浅色都应成立，配色只是层次的一部分。

大标题、日期标签和正文使用明确的不同排版角色，复用已有字体栈；正文保留舒适行宽和行高。颜色去掉后，日报、周报和主题页仍应在结构上可区分，才算完成了构图重做。

### 5. 动态围绕阅读动作编排，正文保持稳定

**本站设计推断与初始参数：** 首次进入栏目时，身份图形用约 500–700ms 完成一次展开或轨迹描绘，标题用不超过 12px 的位移进入；首屏可见的少量内容按约 40ms 间隔出现，累计错开不超过 200ms。日期切换或筛选选择用约 180–240ms 的位置／透明度反馈。以上数值是待验证的起点，不是参考站实测参数。

日报的动作是刻度与日期高亮，周报是封面／纸面展开，主题是索引定位与关系引导线出现。细指针视差只作用于栏目页头的一块装饰图形，建议幅度 4–6px；进入正文后结束。悬停与键盘聚焦具有对应反馈，正文和重要按钮不持续漂移。

优先采用 CSS、SVG 和既有的观察器机制。不要为这些内页增加常驻 WebGL、逐卡片 RAF 或整页继承变量的逐帧更新。离屏与后台停止动作；减少动态效果时直接呈现完整静态内容；图片或脚本失败时标题、正文、目录和来源仍可使用。Stripe 的静态备用思路可借鉴，具体实现应按本站此前已发现的性能热点选择，而非直接搬用其历史代码。

## 实施与验收边界

本轮已将调研落实到主导航的五个内页及共享导航，科技版使用独立 DOM，报刊版保留独立结构。已认可的首页艺术首屏沿用原有实现；搜索、归档和文章正文不属于本轮五种新模板的实施范围。

| 页面 | 已实现的构图与阅读动作 |
| --- | --- |
| 日报 | 真实发布日期的大日期索引、最新报道、往期日期时间线；保留来源、覆盖日期、RSS 与接口失败重试。 |
| 周报 | 真实文章封面构成有书脊和纸面深度的期刊，往期错落排布；不推算期号、不编造目录。 |
| 主题 | 真实主题的坐标索引、已载入数量与本地筛选；圆环仅作索引装饰，不画无数据支撑的主题关系连线。 |
| 系列 | 真实系列封面的立体书架、书脊与书页，结合收录数、最近日期及订阅入口。 |
| 阅读指南 | 六种阅读节奏按钮切换路径预览及真实目标，下面保留完整阅读入口与日期、来源说明。 |

导航提供当前位置、编号栏目、搜索与风格切换。手机通过菜单访问更多栏目和阅读记录，避免沿用桌面弹层后向屏幕左侧越界。

动态由共享 `useTechPageMotion` 管理：封面只在细指针悬停时通过单个 RAF 更新透视变量；内容入场使用一次性观察器，已移除的内容释放观察，卸载、偏好切换和后台切换清理相应监听与待执行帧。封面具有一次性入场和局部悬停反馈，减少动态效果时静态可读。没有增加内页 WebGL 或逐卡片动画循环；未测量真实设备帧率。

本地完整前端验证：87 个测试文件、460 项全部通过；正式 API 构建完整生成 88/88 个主题、5/5 个系列和 141/141 篇文章。额外的 34 项定向回归验证了导航兼容、失败重试、风格结构切换、筛选、阅读路径切换及动态清理。静态审查修复了手机桌面弹层的定位问题，并收窄最小屏的装饰书架展开范围。

2026-10-24 使用已登录的 Chrome 访问 Vercel 分支预览，实际检查日报／周报桌面构图、390px 周报，以及 320px 系列／主题／阅读指南；所查最小屏页面的 scrollWidth 与 clientWidth 相同。实页操作验证手机菜单导航、主题筛选匹配／空结果／清空、阅读路径预览及 /weekly 目标，以及报刊／科技结构切换。截图保存在 frontend/output/tech-*.jpg（本地产物）。同时修正主题接口中已确认的英文内部占位描述，回落现有中文说明，并补回归测试。上述为浏览器窗口宽度与操作检查，尚未覆盖真实触屏设备、逐帧动态录制或帧率测量。

验收需要同时看：

- 桌面缩略图与去色对照下，日报、周报、主题的构图能否区分，视觉主体是否为真实内容。
- 320／390px 的内容顺序、分页、日期控件及目录是否完整可达，不能靠隐藏整页溢出来掩盖问题。
- 冷加载、无数据、部分模块失败、重试及查询切换时，旧结果不会冒充当前结果。
- 减少动态效果、纯键盘、脚本或图片失败时是否仍可阅读；非活动图形不产生持续动画开销。
- 内容型内页的绘制与交互成本是否符合实际设备表现。未测量之前，不承诺 60fps 或声称已经提升性能。
