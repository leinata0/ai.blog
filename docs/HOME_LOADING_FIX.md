# 2026-10-25 首页加载修复

## 已确认的原因

截图中的新闻一览、周报与主题同时显示骨架，发生在内容数据可用前。

- 首页 HTML 已有完整快照：10 条文章、141 总数、3 条周报、4 个主题和 1 个系列。本次首页 HTML 的两次 TTFB 为 1.451 / 1.848 秒，完整传输 2.473 / 2.517 秒；不能把单次缓存命中等同于每次网络更快。
- 首页以外的 HTML 没有首页快照。从日报或文章首次进入首页时，没有可同步使用的首页数据。
- SiteProvider 离开首页主动清空 bootstrap。返回时，“已消费”的构建快照也不能复用，三个内容区域重新等待网络。
- 轻量 home-bootstrap 刷新不含主题，而且会把周报与系列归一为空，整体覆盖完整快照。HomePage 重挂后，补充模块又要重新请求。
- 首页主列表原先先等聚合接口，失败后还等 settings，最后才请求 posts；默认各 30 秒。文章请求把真实超时的 AbortError 误当作导航取消，可能永远不结束加载。
- 实测轻量聚合 / 模块 / 主题接口 TTFB 约 1.351 / 1.156 / 1.777 秒，后端 app 约 103 / 169 / 291ms；均 Vercel MISS、Cloudflare DYNAMIC。没有据此证明 Render 冷启动或数据库是本次主要瓶颈。

首页已有的 Three 动态场景与上述数据请求没有前置依赖，本次不修改场景、动画或排版。

## 修复边界

1. 所有公共 HTML 提前注入有明确时间、schema 和体积上限的完整首页公开摘要，构建复用原有数据请求。首页之外的文档也能在 SPA 首次进入首页时立即提供内容，私有 shell 不注入。
2. 单独保存最新首页状态，离开页面不丢弃。源时间不续期，较新空列表能权威覆盖旧数据，旧 CDN 或旧构建不能在刷新后复活已撤内容。过期内容仅作为带日期提示的短暂核验预览，最多 8 秒；失败或超时停止展示过期内容。
3. `/public-data/home.json` 复用现有 Node Function，只并行访问两个固定公开 Render 路径：完整 home-bootstrap 与 limit=4 的 topics。共用 5 秒服务端预算、固定字段白名单与 128 KiB 输出上限；两路均成功才发布完整快照，不把失败伪造成空栏目。浏览器请求总预算 8 秒，共享进行中请求。
4. 正式域名请求省略凭证；受 Vercel 保护的部署预览保留平台会话。用户头不向 Render 转发。成功公开结果沿用 Vercel 60 秒 + SWR 120 秒缓存，原四栏目的路径与私有 API 边界不变。该路径始终只含公开数据，CDN 可向带 Cookie 的请求发送同一公开缓存。
5. 默认首页由一个完整快照管理，列表不再受 settings 阻塞，模块不再重复请求。搜索、标签和分页保持独立请求；真实超时必须结束骨架并显示重试入口，只有真实取消或已过时的请求可静默退出。

## 验收与回退

应覆盖：首页以外直接进入首页、首页 → 日报 → 首页、慢/失败响应、旧构建预览截止、新空结果、较旧 CDN 晚到与模块重载、默认与查询状态隔离；生产页面确认新闻流、周报、主题和系列都有真实内容，保留动态场景。没有测量整页 LCP/FPS 时不宣称相关提升数值。
